## Resolver boundary

Add an internal RecoveryWorkspace trusted resolver capability constructed only by WorkspaceDO from an explicitly named deployment service binding. The HTTP body, headers, restored SQL/chunks, manifest and request-carried context may not provide a function, URL, service name or resolver implementation. Do not use env string reparse or a callback closing over ctx.ledgerAnchor as a production provider. Actual binding provider remains absent by default; schema16 restore/control returns RECOVERY_UNAVAILABLE before new effects. Do not add a public resolver endpoint or new CLI command.

Proposed fixed input: workspace_id, environment_id and object_name selected from trusted workspace identity. Proposed bounded result: the same three identity fields, authority_epoch, ledger_sha256, generation. All identifiers validate existing slug bounds, epoch/generation are safe positive integers, digest is lowercase64hex, exact closed shape and maximum2KiB. Trusted binding identity is fixed in configuration/release evidence, not returned as self-attestation. No tokens, URLs or secrets in result/logs.

The provider contract requires an independently authoritative, linearizable current read and monotonically increasing generation for every anchor change. This is a runtime integration requirement, not proven by interface typing or a mock. Same generation with changed digest/epoch is invalid; lower generation is invalid; any generation/anchor mismatch with admitted job blocks that job. A later generation with unchanged hash also blocks rather than silently adopting a changed control epoch. Persist admitted resolver identity/generation/epoch/digest in the existing bounded versioned restore job, not a new table. Never accept a caller-selected fallback anchor.

## Guard protocol

Before first admission, after each awaited cryptographic operation or object read/write/hash, and before the next external effect or final SQL publication, await a new bounded resolver read and compare it to the exact request anchor and persisted admission snapshot. After resolver await, synchronously recheck local proof expiry, workspace identity, target epoch/installation digest, maintenance generation, job/step/pending reservation and binding identity. The resolver call itself is the fresh observation; do not recursively invoke another lookup merely because that lookup awaited. No cache survives an external await.

Timeout/failure/invalid response/missing binding denies continuation and does not publish success. Use bounded timeout/response size/one read per guard; no infinite retry. Use a 2,000 ms per-lookup deadline, with late results ignored and no automatic retry; this is a bounded local controller budget, not a provider latency SLA. Test with fake clock where possible rather than weakening existing suite timeouts. A write already sent before rotation can still land; post-await failure must retain pending/uncertain continuation and forbid any subsequent effects or publication. Do not claim cancellation proves no remote effect or delete a possibly-written object.

If the anchor changes mid-job, fail closed and retain evidence. No automatic job rebasing, ledger replacement, target wipe or revival. Operator must use a separately authorized recovery procedure/new isolated target; this issue does not invent a reset operation.

## Pending versus completed control replay fences

Retire/resume intentionally advance maintenance generation; comparing a completed retry with the saved pre-transition fence would incorrectly reject a lost response. For all current16 control operations, use the bounded internal admission record (including target restore controls, not only source captures) with an explicit pending/completed discriminant. Pending guards require exact original admitted local fence/state/job checkpoint. The final transaction performs the authorized transition and atomically writes the public receipt plus completed internal admission evidence containing exact post-transition epoch, installation digest, maintenance generation/state/barrier/capture identity and public outcome digest. Persist no full signed input records. Retirement's post-fence must be recorded internally; ResumeReceipt old/new generation alone is not the entire authority check.

An exact completed retry authenticates current proof/principal/full original fingerprint, reads fresh resolver and then requires the recorded **post-transition** fence and outcome digest. This narrow completed branch runs before pending-job captured/restored-state predicates, returns only the prior public outcome, and performs zero effects. It cannot execute retire/resume again or authorize unrelated operations. Do not invoke assertCurrentCaptureJob's captured-state restriction on an already-retired matching completed replay. Any later maintenance/fence/epoch/installation/anchor change rejects; an apparently similar state with different generation is not equivalent. A receipt without matching completed internal admission cannot use this exception. Preserve all historicalV1 paths. Test lost responses after source retirement and target resume, eviction, duplicate calls, changed post-fence, malformed/incomplete receipt+admission pair, rotation after completion and concurrent control operations. Partial pair creation is impossible inside the same SQL transaction; simulated corrupted pairs fail closed.
