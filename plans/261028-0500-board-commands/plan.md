## Design decisions and invariants

1. One in-memory active task intent at a time across board/detail. Explicit action menu is primary accessible path; pointer drag is optional alternate entry into exactly the same command/dialog. Drag only backlog→ready and eligible review→done. No drag into Doing/Waiting, no external/cross-workspace payload commands. Narrow screens keep action menu usable.
2. Consequential submission requires fresh successful workspace access and exact-task read in one current authority/connection generation, matching session/workspace/selected target; latest run corroboration where acceptance needs it. A recent list card alone is insufficient. Refresh on opening command, reconnect and conflict. While fetch incomplete/failed/stale/unknown: disable submit. Changing task/version invalidates preparation and requires deliberate confirmation with visible new version; never silently overwrite frozen draft intent.
3. Introduce command-specific generation invalidation for offline, navigation, logout, new access refresh and revocation. Late reads/results cannot reenable actions or update another task. Global401/403 uses existing invalidateAll and clears all sensitive drafts/intent/session state. Workspace grants and stable principal come from current Workspace actor, crosschecked session identity; role label is not authority.
4. Pending/uncertain blocks any replacement task intent. Unknown transport outcome, invalid success envelope or5xx keeps exact original key/path/body; explicit replay only (never new key, changed version/body or automatic retry). On reconnect replay waits for current access but does not adopt fresh task version; no pre-replay state gate that prevents retrieving a succeeded original outcome. Genuine revocation clears sensitive state per existing policy. No persistence in local/session storage, URL or logs.
5. Version conflict preserves reason/draft, disables old submit, fetches current access/task, shows conflict/current version and requires explicit review/new action/new key. INVALID_STATE and other known rejection must remain explicit, not masquerade as version conflict or success. New attempt after reviewed known rejection is distinct. Success means validated server receipt only; refresh bounded affected columns/detail afterward; failed refresh does not erase confirmed outcome or infer current state. No optimistic card relocation.
6. Keep command dialog DOM stable while background reads update; preserve text/caret. Accessible name, labelled reason input and visible close control; keyboard focus contained, Escape closes UI without cancelling an already dispatched command, pending intent remains available. Explicit completion may restore focus to affected card/task link or selected detail heading if bounded pagination no longer contains it. Background updates never steal focus. Use polite live region for user-triggered command outcomes; no fabricated global state counts.
7. Explain disabled reasons separately: permission missing, self-review, stale/unavailable authority, invalid task state, R3-only approval unavailable. Do not apply Ready's flag prohibition to Requeue blindly: backend deliberately differs. Cancellation copy explicitly cannot undo agent external effects.
