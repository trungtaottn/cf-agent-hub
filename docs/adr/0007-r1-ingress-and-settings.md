# ADR 0007: R1 ingress, settings and operator recovery contract

Status: Accepted contract amendment · Implementation pending.

The R1 foundation needs explicit authority, browser admission, settings transport, event discovery, delivery bounds and recoverability before runtime work can start. This decision is the informational OpenAPI amendment `r1-foundation-1` on `/v2`. Portable profile and preferences remain revision 0.1; only deployment configuration advances to 0.2. All newly introduced objects are closed. [OpenAPI](../../spec/openapi.json), [deployment schema](../../spec/deployment-config.schema.json), [bootstrap schema](../../spec/r1-bootstrap.schema.json), [recovery manifest](../../spec/recovery-manifest.schema.json) and [recovery command](../../spec/recovery-command.schema.json) are the executable shape authorities. All capabilities remain Specified.

## Operator authority and credentials

Deployment 0.2 requires a positive `config_epoch`, `human_grants`, `static_credential_refs` and `workspace_policies`. A static participant is an identity record, never a grant. Human grants bind exact issuer/subject, stable principal slug, workspace, explicit scopes and project IDs. The issuer/subject pair maps immutably to a principal; display name/email grants nothing. Native credential references bind workspace, credential ID, agent, explicit scopes/projects, enabled state and required RFC3339 expiry no more than 90 days after provisioning. Native R1 scopes are `workspace:read`, `messages:send`, `messages:read`, `messages:ack`, `events:read`. Human-only scopes are `messages:review`, `profile:edit`, `operations:read`; humans may additionally use workspace/message/event scopes. No task/runtime scope is admitted. Policy intersects each participant restriction; neither identity nor policy supplies implicit grant defaults.

Each policy lists unique allowed preference overrides from `theme,density,default_view`, bounded provider retry hint and operator-approved notification destinations. Destinations require exact HTTPS host/path on default port 443; userinfo, fragment, IP literal, loopback/private/metadata target and redirect are refused. Reviewed host allowlisting is the egress boundary if DNS controls are insufficient. Signing key references resolve only to secret bindings. There is no user-supplied callback URL.

An opaque native token is 32 random bytes encoded base64url, generated once by the operator helper to a protected selected descriptor. Ordinary output contains metadata; the named hash bundle is exclusive 0600 outside the repository. The authenticated bootstrap bundle stores SHA-256 hashes, never raw credentials or signing/client secrets. Its `config_digest` binds canonical validated config. `installation_digest` binds canonical `{config,credentials,retired_credentials}` with both credential arrays sorted by workspace ID then credential ID. A protected operator HMAC authenticates the bundle content excluding its tag. Current references and hashes match exactly; retired IDs/hashes are permanent nonoverlapping tombstones. Internal installation stores verification material in protected workspace SQL.

`create` generates exactly one fresh configured credential ID. `assemble` changes config or explicitly retires an ID with no token generation. `install` reconciles through an internal binding. Every update requires authenticated `--prior-config` and `--prior-bundle`; `--initialize` alone applies to empty authority. Verify prior signature/digest/epoch and immutable actor/hash mapping, preserve retained hashes, advance epoch, reject a retired-ID reintroduction, and read installed authority on every command. Lower epoch is rejected; same epoch with changed installation digest conflicts. Rotation creates a new ID, verifies narrowly scoped replacement access under a higher epoch, then disables predecessor under another epoch. Lost reveal is replaced and retired, never recovered. Revocation is complete only when all affected workspace authorities acknowledge the greater epoch. Older Workers cannot reinstall removed grants; recovery reapplies latest signed-off authority before admission.

The security baseline's human-session issuance rule applies to R2 dynamic issuance/scope expansion. R1 has the narrow trusted deployment-operator offline/binding exception, recorded by operator change record and installed-config event. Product `/credentials` and revoke routes remain unavailable, so this does not claim F12.

## OIDC and browser transport

R1 accepts exact configured HTTPS issuer discovery, reviewed HTTPS endpoints and RS256 authorization-code ID tokens with PKCE S256. The `client_id` equals audience. Exactly one exact HTTPS redirect URI per catalog workspace ends at its `/v2/workspaces/{workspace_id}/auth/callback`; session TTL is 300–28,800 seconds and capped by token expiry. Signature, issuer, audience, applicable azp, exp, iat and nonce are verified. Token `jku`/`x5u` and arbitrary Access identity headers are not authority. Unsupported provider subset or algorithm fails admission.

`POST /auth/start` is same-origin and creates a five-minute one-use state/nonce/PKCE transaction plus HttpOnly transient cookie for an allowlisted relative UI return path. `GET /auth/callback` verifies state/cookie, exchanges code server-side at the exact redirect and consumes the transaction before rotating an opaque session. It is the sole narrowly specified mutating-GET exception; it exposes no domain resource command. Replay/expiry cannot mint another session. Failure clears the cookie and exposes no token. `GET /auth/session` returns actor, in-memory session-bound CSRF token and expiry with no-store. `POST /auth/logout` takes `{}`, exact Origin and CSRF, revokes server session and expires cookie. The host-only `cfhub_session` is Secure, HttpOnly, SameSite=Lax, Path `/`; it binds workspace, principal and installed epoch with no silent refresh. Workspace mismatch, revoked membership and conflicting credential lanes fail. Start/callback/health alone are unauthenticated. Session/logout require verified current enabled human grant but no domain scope; this lets a profile-edit-only member bootstrap CSRF. Ordinary human domain writes require Origin, CSRF and idempotency.

## Settings and observability

The R1 [HTTP route table](../http-api.md#r1-foundation-amendment) adds redacted `GET /configuration`, profile read/preview/apply/export, caller-only preferences read/apply, human operations/readiness, auth protocol and public minimal liveness. `/configuration` exposes capability projection, never full deployment config. Deployment/policy have no writable public product endpoint. Settings writes carry expected revision; stale writes return 409/current revision. Profile stable-ID upsert preserves omitted records. Referenced project/role archive/remap waits for R2. Preview is advisory noncommitting POST: required idempotency key correlates recomputation but stores no durable outcome, so it cannot promise same-key changed-payload detection across restart. Apply rechecks revision and persists ordinary durable outcome. Changes/conflicts are closed JSON Pointer entries, at most 200 each; total 65,536 UTF-8-byte envelope overflow fails explicitly without partial application. Readiness check names/codes are bounded closed values, at most 64.

The HTTP baseline's settings deferral is superseded for these exact R1 routes. No delivery replay endpoint is created. Inboxes remain native-only; polling is the recovery path.

## Event attribution and discovery

The public closed Event requires `request_id`, nullable `resource_version` and nullable `thread_id`. Settings variants have stable IDs/versions and null task/run/fence/thread: configuration uses workspace ID/config epoch and verified system operator identity plus internal install receipt; profile uses workspace ID/profile revision and actual human editor; preferences uses an immutable opaque owner record ID/preference revision and actual owner. Their summaries are fixed templates with no changed text, identity subject, hash or secret. Configuration requires human `events:read` plus `operations:read`; profile requires `events:read` plus `workspace:read`; preferences requires those plus owner principal equality, hiding all foreign ID/count/summary. Original command request ID is retained; delivery-origin processing has its own request ID internally linked to delivery ID. The system actor remains an Event type, not a command login lane.

`message.accepted` exposes the persisted thread ID only after current message/thread authorization. It requires `events:read`, `messages:read`, fixed-thread access or human `messages:review`; inaccessible/deleted message events are filtered. Other events have null thread ID. Newly authorized reviewers traverse visible retained events under existing cursor/high-water rules and follow `/threads/{thread_id}`. No ID decoding or new discovery route is required. Nonrecipient accepted/view acknowledgment is null; recipient reads expose only the actor's ACK.

## Finite R1 release and recovery

R1 message DTO stays unchanged. Task/artifact references and nonempty `artifact_ids` return pre-mutation 400 `INVALID_REQUEST` with `details.feature` of `tasks` or `artifacts`. Message references require access for every fixed-thread participant. Unknown/unavailable later-release routes return generic 404. The retry policy is six total attempts with nominal 5/30/120/600/3600-second delays and downward jitter 0.8–1.0; bounded provider hints extend due time by `max(nominal*jitter,min(validRetryAfterSeconds,retry_after_max_seconds))` without adding attempts or shortening nominal backoff. Cursor lifetime is 3600 seconds, dispatch batch 25, attempt lease 30 seconds, callback timeout 10 seconds and scheduler repair every 60 seconds.

The [operator recovery runbook](../runbooks/r1-recovery.md) specifies the first R1 logical SQL/message/outbox recovery. A separate Access-protected operator Worker invokes binding-only methods; the public Worker has no reverse binding to operator credentials. The control envelope and binary transport are finite, with exact header names and canonical base64url metadata. R1 manifest and ledger are separately authenticated. A durable barrier and latest current authority protect restored admission; uncertain delivery requires external evidence resolution and no automatic redrive. Resume requires fresh probe, complete verified receipt and exclusive-authority proof. R2 extends this versioned recovery mechanism with task/runtime/fence/artifact-byte invariants. A platform limit narrower than this contract fails closed pending reviewed amendment.

### Endpoint pinning closure

Deployment authentication additionally requires closed `reviewed_oidc_endpoints:{authorization_endpoint,token_endpoint,jwks_uri}`. Each pin is a canonical absolute HTTPS URL of 9–2,048 characters (`new URL(value).href === value`) with an operator-approved exact hostname/path, no wildcard, credentials, query, fragment, explicit `:443` or other normalization, IP literal, loopback/private/metadata target. The discovered issuer must equal configured issuer exactly, and all three discovered endpoint strings must equal their installed pins exactly. Mismatch fails before token/JWKS fetch or authorization URL use. Server-side discovery, token and JWKS fetches refuse redirects. The browser may follow the provider's ordinary login redirects: its initial authorization URL uses the pinned authorization endpoint with only server-generated OAuth query parameters, while callback stays the exact configured redirect URI. Unsupported provider shapes fail closed. This is a static operator-reviewed egress boundary, not a claim of DNS-level private-address protection.
