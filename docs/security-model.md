# Security model

Status: Design baseline · Contract revision 0.1 · Implementation pending.

CF Agent Hub is planned as a self-hosted coordination service for humans and external agents. It stores work, decisions and artifacts; it does not sandbox agent execution. This document owns the proposed security policy. “Must” states a requirement for implementation and verification, not a claim that a control has shipped.

## Assets, adversaries and boundaries

Protected assets include workspace records, membership and grants, approval authority, credential material, artifacts, audit events, delivery configuration and deployment bindings. Relevant threats include an unauthenticated caller, a compromised runtime with limited grants, an authorized member attempting cross-workspace access, hostile artifact/message content, a malicious callback receiver and an operator mistake. Compromise of the Cloudflare account or trusted deployment pipeline can subvert this boundary; least-privilege account permissions, reviewed releases and recovery controls remain operator responsibilities.

| Boundary | Trusted decision | Required rejection |
|---|---|---|
| Client → Worker | Authenticate principal and validate request envelope | Forged identity headers, invalid issuer/audience, oversized input |
| Worker → workspace object | Map route workspace through deployment catalog | Caller-selected object name or unknown catalog entry |
| Command → stored resource | Current membership/grant, actor kind and same workspace | Foreign task, run, artifact, cursor or approval references |
| Hub → external runtime | Issue bounded work ownership | Stale fence, wrong runtime, self-accepted result |
| Hub → R2 | Exact private key with committed metadata | Arbitrary object paths and uncommitted or foreign downloads |
| Outbox → external destination | Current authorization and egress policy | Revoked grants, unsafe destinations and uncontrolled redirects |

One Durable Object per workspace provides an application partition. [Private transactional storage](https://developers.cloudflare.com/durable-objects/best-practices/access-durable-objects-storage/) does not automatically implement tenant authorization: every command must enforce the partition and all supplied resource relationships.

## Human authentication and browser policy

Human principals are keyed by verified issuer and subject. Display name, email, model, framework and work role never authorize an operation. The chosen Access/OIDC integration must validate signatures with trusted keys, issuer, audience, expiration and applicable protocol claims. A header carrying identity is not trusted unless its assertion is verified. Cloudflare documents [Access JWT verification](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/); generic OIDC integrations must follow [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html), including flow-specific validation. The exact provider configuration belongs to deployment policy, not a profile import.

Authentication establishes identity; workspace membership and action policy determine access. An identity-provider allow rule must not automatically grant every workspace or application administration. Membership removal must reject future commands regardless of an unexpired provider session. Any authorization cache must have explicit invalidation that preserves this requirement.

Browser authentication must use secure, HttpOnly cookies where application sessions are issued, with a deliberate SameSite policy. Cookie-authenticated mutations must require an allowed same-origin request and a session-bound CSRF mechanism. Verify Origin and applicable request context; do not infer safety from JSON content type alone. GET must not mutate domain resources; the R1 OIDC callback is a narrowly scoped one-use protocol exception. Reject conflicting authentication contexts instead of selecting the most privileged one. Credentialed CORS must allow only reviewed origins and never use a wildcard. Enforce content security policy and output escaping; render messages and artifact names as untrusted data.

Native API bearer credentials must not be stored in browser localStorage or shipped as hidden UI configuration. A browser approval must be an explicit authorized human action on the current proposal; a tool invocation or agent assertion cannot stand in for that decision.

## Native credentials, scope and revocation

Native credentials are high-entropy opaque workspace-scoped bearer values. They must be revealed once, stored as verification hashes, compared safely, and associated with a grant identifier, actor, permitted operations, expiry when configured and revocation state. Signing/encryption secrets are separate and must not be derived from recoverable bearer values. R2 dynamic credential issuance and scope expansion require explicit administrative authority through a human session; agents cannot elevate their own grants. Credential lifecycle and agent creation/edit/archive are human-session-only operations. Approval approve/reject also requires a human session. Claim, request-decision, submit-result, fail and run heartbeat are native-runtime operations bound to the active agent/runtime; runtime enrollment and heartbeat must preserve that binding. Accept-result may use an authorized human session or a native `tasks:review` grant, but both the submitter principal and the submitting agent are prohibited from accepting their own result. Message review requires the human-only `messages:review` read authority. Thread membership is fixed; a reply must not expand participants or reveal earlier history to a newly introduced recipient. The [HTTP API](http-api.md) owns the complete scope and actor-kind matrix.

The authenticated route workspace, grant workspace and target resource workspace must agree inside every command. A client-supplied agent ID, runtime ID or work role is not proof of ownership. Runtime identity must be bound to the credential/grant and current run. Enrollment reveals a one-time opaque `runtime_token`; retain only its verification hash, bound to workspace, agent, runtime and issuing native credential. Claim, execution commands, run heartbeat, runtime heartbeat and run-bound artifact writes must verify both the native bearer credential and `X-Runtime-Token`. A runtime identifier alone is not proof. Never log runtime proof material, include it in exports or expose it through ordinary reads. Revoking, expiring or rotating the issuing credential, or expiring the runtime, invalidates its proof. Enrollment returns `{runtime,runtime_token,revealed}` with proof material only on the first reveal; an idempotent replay returns `runtime_token: null` and `revealed: false`. If the reveal is lost, enroll a fresh runtime rather than attempting to recover the secret; the old runtime cannot be used without its proof and its presence eventually expires. Credential rotation requires a fresh runtime enrollment; it cannot reuse an old runtime or run. Drain and reconcile old work, end its authority safely through completion, cancellation or lease expiry, then require a new claim under the replacement runtime. Lost credentials are replaced, never retrieved. Revocation must block the next command and invalidate grant-dependent queued effects. Rotation requires testing the replacement and revoking the predecessor; incident containment can require immediate revocation before replacement.

Credential values, authorization headers, session cookies and provider tokens must be redacted at ingestion from logs, events and diagnostics. One-time reveal is an explicit response exception; it must not be cached or repeated by later list/read operations. Audit credential identifiers and outcomes instead of secrets.

## Task, approval and replay authority

Atomic claim checks task state/version, eligibility, WIP policy and grants. Each run binds agent, runtime, lease and monotonic fencing authority. Stale or cancelled runs must fail even if their credential is otherwise valid. Heartbeats renew the run without changing task/proposal versions. Restore must prevent fence reuse as defined in [backup and restore](backup-restore.md).

Task mutations require expected versions and operation-specific schemas. Generic metadata updates cannot change state, owner, run or decision fields. Approval decisions must match the current proposal and assigned authorized human scope. The proposal must bind authorization-significant inputs to a committed immutable `application/json` artifact through `{artifact_id,sha256}`; summary text alone cannot authorize an action. Execution must match that exact binding and current policy. A submitting agent cannot accept its own result; ACK and transport acceptance never complete work. [Task lifecycle](task-lifecycle.md) owns transition details.

Mutation idempotency is scoped by workspace, principal and operation with a canonical request fingerprint. A matching replay returns the stored result; a different payload conflicts. State, events, outbox and idempotency outcome must commit in one workspace SQL transaction. External calls occur afterward. A failure marked `outcome_unknown`, or exhausted execution retry budget (`retry_exhausted`), must enter a Backlog hold that blocks Ready, requeue and claim, regardless of remaining retry budget. External reconciliation is required; the baseline has no implicit hold-clear command, so recovery uses separately reviewed replacement work after reconciliation. An approved Ready task must not change approved intent through a generic task PATCH; cancel and create reviewed replacement work when that intent must change. This prevents one class of local replay inconsistency but does not promise exactly-once external execution. Consumers and runtimes must reconcile irreversible effects themselves.

## Artifacts and outbound requests

Private R2 bytes require a committed, same-workspace metadata record and authorized download. Server-generated immutable object keys must not accept caller path traversal or arbitrary bucket selection. Staged/uploaded/committed transitions verify size and application checksum before exposure. Active run ownership must be rechecked at finalization. Cleanup must atomically mark an uncommitted artifact `expired` as a durable cleanup tombstone before deleting bytes; upload/finalization reject intents past `expires_at` or in `expired` state. This excludes concurrent commit, while late in-flight bytes remain uncommitted orphans for bounded cleanup. Download headers must prevent unsafe inline interpretation of active content; content type and filenames are untrusted. Quarantine/scanning policy, if required by an operator, must gate availability rather than merely add a UI warning.

Dynamic callback URLs require explicit egress policy: approved HTTPS origins/ports, no userinfo or fragments, no local/private/link-local/metadata targets, validated resolution where the runtime permits it, and controlled redirects with revalidation or refusal. Recheck destination policy at dispatch, not only registration. If the runtime cannot enforce the intended network restriction, restrict callbacks to operator-provisioned origins instead of claiming broad SSRF protection. Do not forward caller authorization headers or arbitrary stored secrets. Signature secrets for deliveries are scoped and rotated separately.

Treat imported tasks, connector content and model-generated text as untrusted data. They cannot modify deployment mappings, memberships or grants. Prompt injection remains a risk in external runtimes; hub approval and authorization checks must not depend on an agent obeying text instructions.

## Audit, incident response and acceptance

Persist server time, principal, workspace, operation, relevant versions/fence, decision and correlation identifiers. Restrict audit access and document retention; an application event log is not automatically tamper-proof against an account administrator. Keep security incident evidence outside a rollback that could erase it.

Before release, demonstrate invalid identity denial, CSRF denial, cross-workspace rejection for every resource family, stale-fence denial, independent review, revocation, secret absence in diagnostics, artifact authorization and egress failure behavior. [Release gates](release-checklist.md) require actual evidence. On compromise, revoke affected grants, pause related delivery, preserve audit context and rotate secrets where exposed. Recovery must reapply current revocations before reopening traffic. Residual risks include malicious authorized content, stolen bearer use before revocation, external-runtime compromise and irreversible effects already performed outside the hub.

## R1 authority and transport amendment

The R1 deployment-operator exception provisions static credentials and grants through a reviewed offline helper, protected authenticated bundle and binding-only install. It is auditable through the operator change record and `configuration.installed` event. It does not expose credential issuance to a public product route. R2 human-session-only dynamic issuance, scope expansion, `/credentials` and revoke routes remain unavailable in R1. Static participant identity and display fields grant nothing; an enabled, exact `(issuer,subject)` human grant or current credential reference, workspace and scope are required separately. A valid provider identity with no installed workspace grant has no access, including on an empty store.

R1 native scopes are `workspace:read`, `messages:send`, `messages:read`, `messages:ack`, `events:read`. Human-only scopes are `messages:review`, `profile:edit`, `operations:read`; humans may also hold workspace/message/event scopes. Explicit credential scope and project restrictions intersect workspace policy with no defaults. A grant in one workspace transfers nothing to another. A credential ID permanently binds actor and token hash; removal is tombstoned. A lost reveal requires a fresh ID and retirement of the uncertain credential. Rotation installs the replacement at a greater epoch, verifies narrowly scoped access, and disables the predecessor at another epoch. Revocation is complete only after all affected authorities acknowledge the greater epoch. An older Worker cannot reinstall removed grants; recovery overlays the latest signed-off authority before admission.

The bootstrap helper generates each 32-byte random opaque token once to a selected protected file descriptor. Ordinary output contains metadata only. Its authenticated hash bundle and deployment configuration are separate; tracked JSON contains no raw bearer or signing secret. The bundle's config digest and combined installation digest bind both config and credential hashes. Every update authenticates prior authority, advances `config_epoch`, preserves retained hashes and retired tombstones; `--initialize` applies only to empty authority. Same epoch with a different installation digest conflicts. Internal install verification material resides in protected workspace SQL.

The supported R1 browser provider profile is exact-issuer HTTPS OIDC authorization code with PKCE S256, RS256 ID tokens, reviewed discovery endpoints and exact callback URI for each catalog workspace. Verify signature, issuer, audience, applicable azp, exp, iat, nonce, state and transient cookie. Token `jku`/`x5u`, arbitrary identity headers and unsupported algorithms/providers confer no authority. Host-only Secure HttpOnly SameSite=Lax sessions bind workspace, principal and installed epoch. Domain writes require exact Origin and session CSRF; callback is a one-use protocol exception to the no-mutation-GET rule. The authenticated session/logout protocol requires current enabled grant but no domain scope. [HTTP API](http-api.md) specifies the exact route lanes.

R1 notification destinations are operator-provisioned exact HTTPS host/path targets on default port 443, with no userinfo, fragment, IP literal, loopback/private/metadata hostname or redirect. A reviewed operator host allowlist is the egress boundary where runtime DNS restrictions cannot be guaranteed. No user callback URL is accepted. `signing_key_ref` resolves only to a protected secret binding, never a bearer or arbitrary header. A separate [operator recovery gateway](runbooks/r1-recovery.md) validates a signed Cloudflare Access service assertion and explicit operation/target allowlist; browser sessions and product bearers cannot invoke recovery methods.

R1 deployment authentication also pins closed `reviewed_oidc_endpoints` for authorization, token and JWKS. Each is an exact operator-approved canonical HTTPS host/path URL with no credentials, query, fragment, explicit port, IP literal or local/private/metadata hostname; discovery strings must match installed pins exactly before use. Server-side discovery/token/JWKS calls refuse redirects. The browser may follow normal provider login redirects from the pinned authorization URL with only generated OAuth parameters. This host allowlist is the declared boundary where DNS-level private-address protection cannot be guaranteed.

#### Human session implementation boundary

The R1 browser flow uses generated canonical OpenAPI request validation and verifies a signed RS256 identity before consulting its explicit installed workspace grant. Successful login atomically consumes the attempt, stores the issuance epoch and a digest of the random opaque cookie, and rotates an existing local session when presented. Provider tokens are never persisted. Attempt secrets are cleared on successful consumption; expired attempts are removed when a new attempt is created. No authentication failure invents an actor or workspace event.

The host-only `cfhub_session` and transient `cfhub_login` cookies have Secure, HttpOnly, SameSite=Lax and Path `/`. Auth responses are no-store and carry a restrictive CSP and no-referrer policy. GET session returns actor, original expiry and a separate-secret HMAC CSRF token for memory-only use. Logout requires exact Origin and that token, then revokes the original session inside current-authority SQL checks. Credentialed CORS reflects only the exact configured callback origin for that workspace. A session cookie combined with Authorization is rejected. Callback failures clear the transient cookie, including unknown-workspace failures.

Error logs contain only a fixed failure category and a server-generated request ID. Deployment HTTP logging and analytics must likewise exclude callback query strings, cookies, authorization headers, provider responses and secrets. Synthetic issuer tests establish local protocol behavior; they do not establish real-provider compatibility or release readiness.

## R2 authority contract amendment — 2026-10-26

[ADR 0008](adr/0008-r2-authority-and-history.md) selects immutable `operator_static | human_managed` provenance in the existing single registry. Preserve exact static references, hashes and tombstones; do not require dynamic records to masquerade as missing static configuration. Cross-provenance collisions or reclassification fail atomically. Migration labels existing rows static and grants no new authority.

A higher authority epoch and every restore overlay revoke human-managed credentials and runtime proofs. Preserve stable identity and retained evidence; active retained agents advance to the current epoch without receiving grants, while disabled/archive state present in authoritative evidence remains inactive. Fresh issuance needs a current authorized human, active agent and current operator ceiling. Never upgrade an old credential's epoch into authentication. Same-epoch same-digest ordinary install remains a no-op; restore is a distinct revocation boundary. Unbacked post-backup dynamic changes cannot be reconstructed from the backup alone; this amendment introduces no newer external ledger.

Human-only imports, profile/operations, credential management, agent management and message review remain denied to native actors. New scope recognition does not authorize existing grants or enable routes; explicit higher-epoch installation is required. Native execution still requires current runtime proof, and scope/role labels never authenticate. Source contract checks do not demonstrate runtime enforcement or live recovery acceptance.

### Local issue25 enforcement boundary

The issue25 source implements human-only agent create/edit/archive and credential issue/revoke, plus bounded identity/credential reads. Management checks the real current session, exact origin/CSRF for writes, current grants and versions before execution or replay. Native callers cannot administer identities or credentials by presenting a forged management scope. Agent records are workspace-wide metadata: their reads and administration require `project_ids: null`. Credential disclosure/revocation requires the complete credential scopes/projects to fit the current human's effective operator delegation/project ceiling (as corrected in issue26), including original retained replay metadata; denial does not rewrite the committed outcome.

Native issuance permits only the canonical operator-native scope allowlist, the issuing human's effective operator delegation/project ceiling, active same-workspace agent and active named project references. Expiry is greater than command time and at most 90 days later. For a static agent, one live current static credential must cover the complete requested grant and expiry; combining scopes or projects across credentials is forbidden. Every human-managed credential also remains beneath its issuing human's enabled current-epoch grant with `credentials:manage`. The original issuing session is not a continuing prerequisite. These shared checks apply to native authentication and background eligibility, not merely issuance.

Entropy and asynchronous hashing finish before the synchronous transaction. The transaction stores the verification hash, sanitized lifecycle event and `token: null`/`revealed: false` outcome atomically. A private post-commit first-execution signal permits the request-local response to reveal the bearer once; it is not a stored field. Neither raw bearer nor a recoverable encrypted copy belongs in SQL, logs, audit, outbox, replay or recovery exports. Same-key response-loss replay cannot issue or reveal another credential. A deliberate replacement uses a new key, then explicit revocation of the uncertain credential. Current authorization still governs replay and final response publication after asynchronous work.

Archive rejects active runs and every nonterminal assigned task. Its status change, all credential/proof revocations, event and replay outcome share the transaction, while identity and history remain. Credential revoke can invalidate an active owner without silently reassigning its run. Authentication and background delivery check archived status and local `revoked_at` independently of operator-enabled fields, so a later static install cannot resurrect either. Public lifecycle events use fixed summaries and canonical null `resource_version`; domain DTO versions remain the mutation preconditions.

This is source implementation, not live acceptance. Issue26 adds local runtime enrollment; task execution and current schema8 recovery remain pending with their owners. The [execution ledger](r2-task-plans/issue-025-execution.md) records exact verification and limitations; historical schema7 recovery tests do not satisfy #39/#43.

### Selected history privacy invariant

The proposed [history read](adr/0008-r2-authority-and-history.md) requires current task access and full current visibility of every artifact reference before returning any part of that result. Selection and continuation use authorized rows only; a cursor advances to the last returned authorized sequence. Hidden-only suffixes terminate without a progress cursor. Under fixed visible data/grants, inserting hidden results must not change successful page contents or continuation shape. The earlier filtered-candidate proposal is superseded: limit-one empty continuations could reveal exact hidden counts, and cursor encryption does not prevent that inference.

This does not promise constant-time execution or eliminate resource-failure side channels. Bounded physical query/authorization work must be demonstrated on the actual storage runtime before activation; supported budget failure returns generic 503 without partial results or cursor. Response bytes are capped at 1 MiB, with admission/restore proof against the maximum supported continuation envelope. Current authentication, absolute expiry, authority epoch and restore incarnation apply independently of cursor confidentiality. These are source/design requirements, not verified endpoint protection.

## R2 import disclosure boundary

Only a currently authorized owning human may preview/read/apply an import; require imports:manage plus tasks:read and additionally tasks:create on apply, with existing POST CSRF/idempotency controls. Recheck current authority before replay or response. A saved immutable preview/report that can no longer be safely disclosed is denied generically rather than partially rewritten. An inaccessible mapping is not disclosed through unchanged/conflict classification; reference absence and inaccessibility share INVALID_REFERENCE. Rejected rows suppress even syntactically valid source external IDs, returning only index/null identifier/null task ID/generic code. Do not echo schema errors, unknown authority fields or source text in error details.

The public preview digest binds the public immutable plan only; it is neither authorization nor a hash of omitted source bodies. Server-side immutable ID-to-source/snapshot binding remains mandatory. Sources cannot import owners, grants, credentials, runs, approvals, accepted results or executable URLs. source_ref is inert provenance text and must never trigger outbound fetching. Source state is preserved as provenance but new tasks become unassigned Backlog. Static fixtures and hypothetical authority contexts do not prove these runtime security checks; issue37 adds separate local Workers evidence, not live acceptance.

## R2 search successful-response privacy amendment

Encrypted hidden scan frontiers still leak traversal shape through empty progress pages and can leak plaintext length through ciphertext size. The [executed synthetic comparison](research/r2-search-contracts/report.md) selects authorized-only continuation, explicitly superseding retained #21/#36 empty-filtered-page requirements. Preserve the 2,000 examined-candidate bound; fail the whole request with generic 503 and no partial data/cursor if authorized lookahead or exhaustion cannot be proved. Do not publish hidden-derived counts or continuation positions. Require padded/fixed-width shared AEAD encoding, current resource predicates before snippets and final reauthorization after cursor crypto.

This protects successful page content/continuation shape under hidden insertions within feasible work; it does not hide status/availability or timing. A hidden-heavy collection can cause 503 where another returns200. Never claim constant-time behavior or total cardinality noninterference. No automatic error-progress token may turn failures back into a hidden traversal oracle. Search authority remains resource-specific, artifact bytes stay unread, and task/artifact-only cursors must not expire from unrelated message retention. Actual physical-work bounds and encoded-payload fit remain required before runtime activation.

## Local runtime proof boundary (issue26)

A runtime token is 256 bits of server-generated opaque entropy. Only its SHA-256 verification material is persisted, bound to exact credential, agent, workspace and authority epoch. Runtime DTOs, events and idempotency outcomes contain neither raw proof nor its digest. The only reveal is a private first-response projection after successful atomic commit; lost responses and restarts cannot reveal it again.

Proof hashing occurs after the ingress admission fence is captured and before SQL. The consuming synchronous transaction rechecks admission generation, current actor and credential ceilings, exact runtime binding, status, revocation and trusted presence deadline. `VerifiedRuntime` is transaction-local server evidence, not a reusable authentication session. `ActorContext.runtimeId` remains null and forged runtime fields remain rejected. Enrollment replay additionally checks the original runtime's issuing credential because idempotency principal identity is the agent, not its individual credential. Heartbeat checks proof before replay but applies version preconditions only to a first mutation.

No SQL transaction awaits cryptography, and runtime routes perform no unrelated post-command scheduler await. Runtime audit production uses fixed summaries; public runtime-event visibility remains fail-closed pending its policy owner. Local [verification evidence](r2-task-plans/issue-026-execution.md) is not live ingress, current-schema recovery, or post-R4 integrated acceptance.

### Explicit delegation is not human execution authority

The issue26 prerequisite correction separates optional operator-installed `delegable_native_scopes` from human action scopes. Explicit lists are exact, `[]` disables delegation and omission retains the legacy native-compatible action-scope intersection. Deleting the field restores fallback, so it is not a revocation operation. The shared predicate re-reads validated current config and current grant identity/epoch/enablement/management permission and intersects project ceilings. No request, role label, actor field or restored source config can supply delegation authority. Full-grant credential reads, revoke, audit visibility and original replay use the same ceiling as issuance and ongoing native/background authentication. The existing static single-grant adoption ceiling remains required. [ADR 0008](adr/0008-r2-authority-and-history.md) explains the integration defect and compatibility decision.

## Local R2 embedded message resources

Issue34 preserves actual caller authentication and fixed thread membership while extending current resource checks to tasks and committed artifacts. Each participant requires one live coherent grant; background eligibility data is not an ActorContext, session or runtime proof. Current artifact associations are conjunctive, not an owner/public/any-message capability. A bounded iterative graph checks every local scope/relationship before following deduplicated edges. Admission validates the resulting reverse association graph inside the transaction. Read/replay/event/dispatch and retained Task.result/history checks do not expose revoked embedded metadata; notification signing is followed by another complete participant check. Successful message POST defers shared scheduler repair through waitUntil without awaiting unrelated I/O after its final authorized projection; existing message/event startup repair remains before authentication. Eligibility seeks only current live credentials through migration14’s partial index, then validates one full coherent graph per credential; retired history is not a lifetime credential cap. Metadata-dependent aggregate-size errors occur only after graph authorization. ACK remains recipient-owned historical acknowledgment, never task completion. See the [execution record](r2-task-plans/issue-034-execution.md) for candidate/graph budgets and staged-source limitations.

## Local R2 independent result review

Issue35 compares the current reviewer's stable principal and stable agent independently with immutable submitted attribution. Matching either identity axis denies; another credential/runtime is not another reviewer, and archived submitter metadata is not erased or re-resolved as current authority. Reviewer's own current grant, issuer ceiling, project and full artifact/message graph remain mandatory. No permissions are unioned across credentials, no ActorContext is manufactured, and R3 approval routes remain closed.

Submission consumes the existing exact active-run assertion and verified runtime proof inside the same synchronous result/run/task/association/event/history/outcome transaction. Cryptographic awaits occur before that transaction and current epoch/maintenance/proof/grants are rechecked afterward. Submission reprojects its new graph and bounded full response before commit. Historical event/result access is checked against its original evidence even after current pointers are invalidated. Replay reauthorizes original returned references without repeating first-execution state/version/lease conditions; submit replay still requires current original credential/runtime presence. Shared scheduler repair uses waitUntil, not an awaited post-projection authority gap.

Acceptance is a local immutable review decision, not proof of external effects, permission to rerun uncertain work or general human approval. Unknown/exhausted holds and retry budgets are not cleared. Private review reason stays internal. [Execution evidence](r2-task-plans/issue-035-execution.md) separates deterministic source tests from unavailable current recovery and owner-scheduled post-R4 acceptance.

## Local issue36 search and ambiguous native secrets

Local search implements the reviewed authorized-result-only rule above, not the superseded hidden-progress proposal. Every candidate uses the current underlying resource graph; authorized lookahead alone creates continuation. A private bounded ledger is rechecked after crypto under the original proof/fence without reopening discovery or ceiling. Generic503 on budget/consistency failure publishes neither partial results nor a progress cursor. Fixed-width AEAD hides cursor plaintext and length, not status, timing or availability; the ceiling is a tuple bound, not an insertion snapshot. [Measured implementation evidence](research/r2-search-runtime.md) separates admitted candidates, physical SQL and repeated graph work.

The shared native verifier now requires exactly one same-workspace hash match before eligibility, with indexed LIMIT2 discovery. Any duplicate, including disabled, expired, revoked, retired or old-epoch history, denies rather than choosing another identity or combining grants. This explicitly changes legacy arbitrary-first behavior while preserving all stored rows. Synchronous current-proof resolution repeats the ambiguity check after awaits and on replay; a new duplicate cannot keep an earlier proof alive. Cross-workspace reuse does not create same-workspace ambiguity. No credential rotation or database cleanup is performed automatically. Current recovery remains unavailable pending39/43; historical frozen wire/schema compatibility is not current restoration evidence.

### Issue37 current authorization and inert-source evidence

The import source uses the original verified human session and admission fence at final transaction entry, including after request fingerprint, preview digest and saved-binding crypto. Current import/task scopes precede saved-content comparisons; apply also rechecks tasks:create. Owner/project/reference loss denies the whole saved response. Mapped/created tasks include current result-artifact commitment, association and message-graph permissions; tasks:read alone cannot disclose hidden result references. Fresh inaccessible rows become generic rejected rows; saved immutable plans are never silently redacted.

Invalid row values—including unknown credentials/grants/owners—are replaced by null before source persistence, and never enter report/event/error/log payloads. Valid source strings remain literal untrusted data. A canonical request fingerprint distinguishes different rejected inputs without retaining their secrets; it is not an encryption or low-entropy-secret confidentiality guarantee. The public preview digest and private corruption checksum grant no authority. Import events expose only fixed summaries and the owning immutable import ID. No execution, approval, outbound URL fetch, recovery activation or external credential creation follows from importing a source state.

## Local issue38 native transport boundary

The typed native facade shares the browser transport but keeps credential lanes separate: native requests omit cookies, reject human-only/disabled operations locally, send proof only on canonical proof-required operations, and never follow redirects. Manual redirect mode is explicitly checked before body parsing; existing browser redirect rejection is unchanged. Exact HTTPS context and caller-owned intent/key are fixed before the asynchronous provider boundary; no implicit login, enrollment, rekey or retry occurs.

A trusted provider pins one protected slot and local generation through a synchronous once-only secret-use callback. Its contract requires nonblocking synchronous currentness/release; arbitrary malicious adapter code is not sandboxed by the client. Runtime-authenticated enrollment mints a private process-local receipt bound to that provider instance and captured slot/generation. Structural labels, nominal types, copied JSON or another provider's receipt cannot substitute. Pending capture receipts activate only after successful capture and currentness recheck. Late acquisition/response bodies are released/cancelled; failed or late capture cannot activate provenance. The server remains the authority for current credential/runtime/resource access.

Issue41 owns durable store integrity, writer control, proven issuance/import associations and journal rebind policy. `expectedBinding` is a comparison constraint, not authentication, and is mandatory for that future journaled workflow even though plain transport callers may omit it. Local errors may arise after dispatch: never infer no-send merely from a credential-change/timeout/capture code. Only an explicit enrollment hook sees the one-time proof; safe results/errors contain no bearer, raw exception/cause or proof. Local exception codes are allowlisted, including errors thrown by trusted hooks or stream producers. Binary streams have finite actual-byte bounds and deadline/cancellation; metadata validation and clean EOF do not claim incremental client-side digest authentication.


## Current capture authority (issue39)

Historical sections retain their checkpoint-specific recovery status. Exact current schema15 now permits only authenticated capture/status/read-chunk, with independent operator proof, workspace/environment/installation identity, epoch and persisted maintenance fence checks before replay/effects and around every asynchronous byte operation. Current restore and mutable recovery controls remain closed. Capture does not impersonate former product readers: it preserves archived attribution and validates structural attachment relationships in both directions. It never treats verification hashes, reserved effects, retained idempotency outcomes or approved-input evidence as renewed execution authority. Login nonce/PKCE secrets are projected empty; raw runtime proofs are never stored/exported. The unexposed unsigned draft is replaced by an HMAC manifest only after actual SQL/artifact coverage and full envelope checks. Failure diagnostics are finite safe codes; the source stays closed on failure and success. Opaque handles do not prove physical bucket separation, so reviewed trusted binding declarations remain mandatory. See the [owning amendment](adr/r2-recovery-contract.md#issue39-current-capture-amendment-revision02-schema15).
