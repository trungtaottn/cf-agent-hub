## Independent design review clarifications

1. `loadDecisionView` binds approval.proposal.inputs artifact ID and SHA to current same-workspace committed metadata ID/SHA/exact `application/json`/safe size/positive artifact version, with null or matching task/run associations only. Current task ID/workspace must match approval.task_id/workspace; historical approval is visibly historical if current task.approval_id differs. Successful `ArtifactDownloadResult` must return exactly the requested metadata, exact size and digest of original bytes, and `completion.ok` with matching byteSize before any input text is published. After download/hash, current access+approval+task+artifact reads must still match the displayed snapshot; changed input or authority drops all text. No comparison equates historical task_version_at_request to current task_version.
2. No browser action registry. UI shows “Request a decision; server checks current policy and action availability” rather than claiming supported execution. Production registry remains empty, so no real pending approval can be admitted; synthetic private fixtures only demonstrate plumbing. Action names and scope badges are inert text, never support/permission evidence. No “verified” authority flag or override enters the public DTO.
3. Host `refreshSession():Promise<boolean>` re-reads actual `/auth/session`, sets only that returned CSRF token on the same HubClient and rechecks current bound human identity. DecisionActions calls it AFTER all optional reads, and immediately before each first dispatch or explicit replay; then reads current workspace authority, checks unchanged binding and frozen revision, and dispatches without any optional intervening read. Any session/authority failure clears preparation; an old cached CSRF token is not reused. Tests reproduce artifact403 clearing the token, recovered fresh token, identity change during final session refresh, and denied refresh causing zero mutation dispatch.
4. Explicit states: `idle`, `preparing`, `review`, `ready`, `confirming`, `pending`, `uncertain`, `conflict`, `rejected`, `succeeded`, `unresolved`. `prepare(id,operation)` performs exact current read and leaves `review`; `setReason` increases reason revision and returns to `review`; `confirmReview()` deliberately freezes the currently displayed observation revision, operation, three current expected versions and reason revision, moving to `ready` only for nonempty schema-valid reason and current eligibility. `submit()` transitions to `confirming` for final session/authority, then `pending` with one immutable body/key. Any predispatch reason/selection/input revision change invalidates confirmation and fences late preparation; dispatch cannot occur after it. Pending/uncertain locks in-component edits and selection only; logout, workspace change and navigation disposal always immediately redact and fence callbacks; refresh may observe authoritative state but never replaces retained intent. `replay()` uses only original immutable body/key, fresh current session and scopes; successful replay is historical admission, current reads are separate. Identity/authority revocation clears raw text/reason/body immediately and leaves only `unresolved` outcome warning; no automatic retry or key replacement.
5. Reason/body use canonical `ApprovalDecisionRequest` plus full serialized UTF-8 JSON body ceiling 65,536; no invented lower reason limit. Error attribution includes frozen reason revision: old response cannot focus or set aria-invalid on a newer reason. Conflict/APPROVAL_EXPIRED preserves reason, refreshes winning current state, and stays `conflict` until explicit `prepare` plus `confirmReview`; no automatic version substitution/expiry renewal.
6. `DecisionReads` owns one content AbortController and one in-flight detail load. Select/refresh/invalidate abort prior transfer and immediately clear raw text. A new load waits for prior bounded promise settlement; an unfinished crypto digest cannot be cancelled, so only one digest promise is admitted, and invalidated late digest is discarded. No background retry of denied/expired streams; retry requires explicit user refresh. Unit tests pin every boundary above, including cancellation during hash, new selection while stream unresolved and inaccessible child clearing list/detail observations.

### App integration contract

Construct one `DecisionReads` per current workspace principal. Reader callbacks delegate to the SAME HubClient (`request('getWorkspace',{})`, `approvalRead`, existing `read` task/artifact reads, and `downloadArtifact`); do not create an independent CSRF owner. Source rendering functions have no native controls, permissions, mutation or automatic polling. New human confirmation flows must separately refresh the actual session CSRF AFTER optional reads, exactly as reviewed above.
