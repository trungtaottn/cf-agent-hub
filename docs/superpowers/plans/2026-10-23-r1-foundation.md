# R1 Foundation and Reliable Relay Implementation Plan

Status: Implementation plan reviewed · Implementation pending.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development for task-by-task implementation with independent review through the authorized execution environment. Keep shared-checkout mutations sequential and follow the orchestration execution ledger. Steps use checkbox (`- [ ]`) syntax for tracking. Implementation requires an available authorized workspace.

**Goal:** Deliver a neutral, authenticated workspace with explicit static grants, reliable durable messaging, truthful reads, validated settings and evidence-backed operational readiness.

**Architecture:** A Worker verifies identity and bounded input, then selects one SQLite-backed Durable Object through the operator catalog. The workspace owns current grants, domain commands, transactional message/event/outbox/idempotency state and read projections. Browser clients consume that contract; notifications leave the transaction through a durable dispatcher, and external agent code never runs in the hub.

**Tech Stack:** TypeScript, Cloudflare Workers and SQLite-backed Durable Objects, private R2 reserved for later artifact operations, Wrangler, Vitest with the currently supported Cloudflare Workers integration, Playwright for browser acceptance, JSON Schema 2020-12 and OpenAPI. Task 2 selects and locks mutually compatible actual versions; this proposal asserts no installed or tested toolchain.

**Spec:** [R1 roadmap](../../roadmap.md), [feature matrix](../../feature-matrix.md), [security model](../../security-model.md), [configuration](../../configuration.md), [delivery semantics](../../delivery-semantics.md), [limits](../../limits.md), [HTTP API](../../http-api.md), [OpenAPI](../../../spec/openapi.json), [data model](../../data-model.md), [customization](../../customization.md), [design guidelines](../../design-guidelines.md), [deployment](../../deployment.md), [testing](../../testing.md). ## Global Constraints

- All capabilities start **Specified**. Plan approval, schema validation and test scaffolding do not establish implementation, verification or release.
- Scope: F01–F10, F27, F28, F30 and F41. The R1 isolation matrix covers every exposed R1 route; F14 later expands it.
- Product name: CF Agent Hub. License: MIT, `Copyright (c) 2026 trungtaottn`. Fresh profiles contain empty projects/work roles; demo content is an explicit opt-in import.
- One stable operator catalog mapping per workspace; no profile rerouting, automatic tenant creation, hidden principal or fallback identity.
- Human identity is verified `(issuer, subject)`; membership and operation grants are separately required. Static participant display names never confer authority.
- Inbox defaults to 50, maximum 200; thread defaults to 100, maximum 500; events default to 50, maximum 200. ACK batches contain at most 200 unique IDs.
- Message body: 32,768 UTF-8 bytes. JSON envelope: 65,536 UTF-8 bytes. Canonical references: 8,192 UTF-8 bytes. The later artifact boundary remains 5 attachments, 10,485,760 bytes each and 26,214,400 aggregate; R1 cannot attach nonexistent artifacts.
- Completed idempotency outcomes survive for at least 24 hours. Replays reauthorize before returning any original outcome.
- Notification attempts: six total; retry delays 5, 30, 120, 600, 3,600 seconds, optional persisted multiplier in `[0.8,1.0]`. Platform alarm retries do not enlarge this budget.
- HTTP DTOs use snake_case. Domain contexts use the interfaces below. No network, crypto await, R2 operation or Promise is permitted inside `WorkspaceTransaction`.
- Native runtime proof is mandatory only for later runtime-bound operations. R1 native send, inbox, thread, ACK and events use a scoped bearer as specified; supplying readable runtime IDs must never unlock unavailable execution routes.
- Error envelopes, stable order, fixed thread participation, current authorization and generic inaccessible-ID errors follow the native baseline. Delivery success and ACK never imply execution or completion.
- Every task gate records exact revision, environment, command, expected/observed result and sanitized artifacts. An unavailable dependency is a stop condition, not a skipped green test.

## Execution dependencies, boundaries and shared interfaces

Execution depends on the separate release-orchestration plan's workspace access, isolated candidate and source-publication gates. All commands below are **planned deliverables**; they are not known to work in the current candidate. Task 1 begins with standalone contract checks; Task 2 owns package scripts. The remaining tasks depend sequentially unless their gate says otherwise. No R1 deployment is exposed until Task 11 passes and the orchestration release gate authorizes promotion.

The exact shared interfaces live in `src/workspace/context.ts` and `src/storage/transaction.ts`:

```ts
interface ActorContext {
  workspaceId: string; principalId: string; kind: 'human' | 'agent';
  agentId: string | null; scopes: ReadonlySet<string>;
  projectIds: readonly string[] | null; credentialId: string | null;
  runtimeId: string | null; sessionId: string | null;
}
interface CommandContext {
  actor: ActorContext; requestId: string; idempotencyKey: string; nowMs: number;
}
interface WorkspaceTransaction {
  all<T>(sql: string, bindings?: readonly SqlValue[]): readonly T[];
  one<T>(sql: string, bindings?: readonly SqlValue[]): T | null;
  exec(sql: string, bindings?: readonly SqlValue[]): void;
}
type SqlValue = string | number | null | ArrayBuffer;
```

`withTransaction<T>(body:(tx:WorkspaceTransaction)=>T):T` wraps documented `storage.transactionSync`; reject an accidentally returned Promise. `Clock.nowMs()` and `Entropy.bytes(length:number)` are injected interfaces, with trusted production implementations. `VerifiedIdentity` is an internal discriminated union of `{kind:'human', issuer, subject, sessionId, workspaceId}` and `{kind:'agent', workspaceId, credentialId, tokenDigest}`; callers cannot serialize one into a public request and bypass verification. `resolveActor(tx, identity, nowMs):ActorContext` reads current installed grants. `authorize(tx, actor, operation, resource?):void` rechecks current authority and resource relationships; an ActorContext is not a forever-valid capability. The R1-owned interface adds `sessionId:string|null` to the brief: humans carry the verified server session record ID, natives carry null. Every human domain call rechecks that record's workspace/principal/expiry/revocation within the transaction, including after an await or logout; principal identity cannot substitute for session identity. `ResourceAccess` carries `{kind,id,projectId}`; `projectIds:null` and `[]` retain their different baseline meanings.

All operation DTO aliases derive from committed OpenAPI schemas in `src/http/dto.ts`; no second hand-maintained request schema. `CommandOutcome<T>={status:number,data:T}` stores authoritative domain results without per-attempt response correlation. Fresh response `request_id` identifies this attempt; replay evidence also links the original command event. Task 1 adds required `request_id` to the public Event schema for original command correlation; delivery-origin events carry a newly generated processing request ID linked internally to the delivery ID. Task 1 documents this explicit clarification.

### Amendment A — explicit operator authority and credentials

Deployment `0.2` adds required positive integer `config_epoch`, `human_grants`, `workspace_policies`, and `static_credential_refs`. Existing `static_participants` remain identity records only. Human grants contain `{workspace_id,principal_id,issuer,subject,scopes,project_ids,enabled}`. `principal_id` is an operator stable slug, unique per `(issuer,subject)` and immutable once installed; issuer/subject are compared exactly, never by email. `scopes` is a unique array of the reviewed R1 scope enum. `project_ids` is null or unique stable IDs. A human grant in one workspace implies nothing elsewhere.

Static credential references contain `{workspace_id,credential_id,agent_id,scopes,project_ids,expires_at,enabled}`; expiry is a required RFC3339 timestamp, maximum 90 days from provisioning as an explicit R1 operational ceiling. R1 native scope enum is `workspace:read`, `messages:send`, `messages:read`, `messages:ack`, `events:read`. Human-only scopes are `messages:review`, `profile:edit`, `operations:read`; humans can additionally receive `workspace:read`, `messages:send`, `messages:read`, `events:read`. No R1 native runtime or task scope is enabled. Per-participant grants are these explicit credential scope/project restrictions, intersected with the installed workspace policy; no implicit defaults.

`workspace_policies` entries contain `{workspace_id,allowed_user_overrides,notification_destinations,retry_after_max_seconds}`; the last field is an integer 0–3,600, default 3,600, with 0 meaning ignore provider hints. `allowed_user_overrides` is a unique subset of `theme,density,default_view`. Each destination is `{destination_id,agent_id,url,signing_key_ref,enabled}`; require HTTPS, exact operator-approved host/path, port 443/default, no credentials, fragments, IP literals or loopback/private/metadata hostname targets; redirects are refused. R1 exposes no user-supplied callback URL. The reviewed operator host allowlist is the egress boundary when runtime DNS restrictions cannot be guaranteed. `signing_key_ref` resolves only to a secret binding, never a bearer or arbitrary request header.

Protected bootstrap bundle schema: `{contract_revision:'0.1',config_epoch,config_digest,credentials:[{workspace_id,credential_id,token_sha256}],retired_credentials:[{workspace_id,credential_id,agent_id,token_sha256,retired_at_epoch}],auth:{key_id,algorithm:'HMAC-SHA256',tag}}`. The helper authenticates canonical bundle content excluding tag using a dedicated protected operator key; provenance cannot be inferred from a filename. Digests are lowercase 64-hex SHA-256 of a 32-byte random opaque token encoded base64url; no raw credential, OIDC client secret or notification signing secret appears in tracked deployment JSON. Bundle `config_digest` must match SHA-256 of canonical validated deployment config; current references and `credentials` match exactly; `retired_credentials` preserves removed IDs/hashes as permanent tombstones and cannot overlap current IDs. Separately compute and persist `installation_digest = SHA-256(canonicalJSON({config,credentials:credentials sorted by workspace_id then credential_id,retired_credentials:retired_credentials sorted by workspace_id then credential_id}))`; use this combined digest for same-epoch equality, so hash-only bundle changes cannot be smuggled through unchanged configuration. Installation stores verification material in protected workspace SQL. A binding delivers the bundle to internal bootstrap reconciliation, never a public admin endpoint.

The operator helper accepts `create`, `assemble` and `install` subcommands and generates a credential once to a user-selected protected file descriptor, emits only metadata to ordinary output, and writes the hash bundle to an explicitly named `0600` file outside the repository. It refuses an existing output file. Every update requires `--prior-config` and protected authenticated `--prior-bundle`; only `--initialize` with empty prior authority permits their absence. Verify prior signature/config digest/epoch and immutable actor/hash mapping, require a greater new config epoch, preserve hashes of all retained IDs, and move deliberately removed IDs to permanent retired tombstones. `create` adds exactly one fresh configured ID; `assemble` performs config-only epoch changes or explicit `--retire <credential-id>` without generating any token. Neither can reintroduce a retired ID. Lost reveal requires a fresh credential ID/value and retirement of the uncertain reference. Rotation installs replacement under a greater epoch, verifies narrowly scoped access, then disables the predecessor under another epoch. Revocation is complete only after all affected workspace authorities acknowledge the greater epoch; do not promise instant globally propagated deployment. Every command reads installed authority. A lower epoch is rejected; the same epoch with a different installation digest conflicts. A previously seen credential ID binds immutably to both its actor and token hash, even at a later epoch; rotation always allocates a new credential ID. Older Workers cannot reinstall removed grants. Recovery reapplies the latest signed-off operator config/bundle before admission and never restores an old epoch as current authority.

**Conflict to resolve explicitly:** the security document presently requires human-session issuance/scope expansion. Add a narrowly stated R1 exception for trusted deployment-operator provisioning through the above offline/binding process, auditable by operator change record and installed-config event. R2 retains human-session-only dynamic issuance; `/credentials` and `/credentials/{credential_id}:revoke` remain unavailable in R1. Deployment labels alone do not satisfy F03. This closes the missing static authentication lifecycle without claiming F12 implementation.

### Amendment B — concrete OIDC and browser transport

Keep `authentication.mode='verified-oidc'`. Add `client_id` (must equal configured audience for this R1 client), `redirect_uris` (array of closed `{workspace_id,redirect_uri}` entries, exactly one per catalog workspace, with exact HTTPS redirect URI ending in `/v2/workspaces/{workspace_id}/auth/callback`), `client_secret_ref`, `session_ttl_seconds` (integer 300–28,800), and `id_token_algorithms` fixed to `['RS256']` for the initial supported provider subset. Discover only the exact configured HTTPS issuer; verify discovery issuer equality and operator-reviewed HTTPS endpoints. Do not trust token `jku`, `x5u`, or an arbitrary identity header. Document the supported provider profile; unsupported algorithms/providers fail admission.

Routes relative to the workspace base: `POST /auth/start` is same-origin only, no native/session credential required, creates a five-minute one-use login transaction with state, nonce and PKCE S256 verifier plus an HttpOnly transient cookie; input `{return_path}` must be an allowlisted relative UI path. It returns `{authorization_url}` in the usual envelope. `GET /auth/callback?code&state` is a narrowly documented protocol exception to the no-mutation-GET rule: validate state plus cookie, exchange code server-side with PKCE and exact redirect, verify ID-token signature/issuer/audience/azp where applicable/exp/iat/nonce, resolve an already installed human grant, consume the login transaction, rotate the opaque session and redirect to the saved path. No resource command is accessible through this exception. A consumed or expired login attempt cannot mint another session. Provider error/callback failure clears the transient cookie and reveals no token.

`GET /auth/session` returns `{actor,csrf_token,expires_at}` with `Cache-Control:no-store`; the CSRF token is session-bound and held in memory. `POST /auth/logout` accepts `{}` plus session CSRF and Origin, revokes the server-side session, expires the cookie and returns `{logged_out:true}`. Session cookie `cfhub_session` is Secure, HttpOnly, SameSite=Lax, host-only and Path `/`; server records bind workspace, principal and installed authentication epoch. TTL is the smaller of configured TTL and verified token expiry; no silent refresh in R1. A session for A is rejected at B. Duplicate credential lanes are rejected, not resolved by priority. Ordinary authenticated mutations require exact Origin and a valid `X-CSRF-Token`; authentication start is protected by same-origin admission and callback state/cookie binding. Auth callback and start are protocol operations with their own one-use identity; ordinary domain mutation idempotency remains unchanged.

**Conflict to resolve explicitly:** the baseline names a session but has no issuance/logout/bootstrap transport. Record the callback exception and the exact supported OIDC flow; never advertise that arbitrary Access headers automatically implement this flow.

### Amendment D — schema-valid audit and human thread discovery

Extend the closed public Event schema with resource variants `configuration`, `profile`, `preferences`, required `request_id:string`, required `resource_version:integer>=1|null`, and required `thread_id:string|null`. Existing task/run/fence fields remain nullable and are null for the new variants. Preserve existing Actor kinds, including `system`; do not extend command ActorContext with a system login lane.

| Event type / resource | Stable resource ID and version | Attribution and visibility |
| --- | --- | --- |
| `configuration.installed` / `configuration` | Workspace ID; installed config epoch | Existing system actor with operator identity from authenticated install context; requires human `events:read` + `operations:read` |
| `profile.updated` / `profile` | Workspace ID, not portable preset ID; profile revision | Actual human editor; requires `events:read` + `workspace:read` |
| `preferences.updated` / `preferences` | Immutable opaque server-created preferences record ID; preference revision | Actual human owner; requires human `events:read` + `workspace:read` **and** owner principal equality; other users/operators receive no event, ID, count or summary |
| `message.accepted` / `message` | Message ID; resource version null | Actual human/agent sender; requires `events:read`, `messages:read` and current fixed-thread access or human `messages:review`; projection supplies the persisted message's `thread_id` |

All other events have null `thread_id`. Message event projection joins the actual message/thread under current authorization before returning the event; inaccessible/deleted message events are filtered rather than returning a dangling or concealed-resource link. A newly authorized reviewer may traverse retained visible message events through `/events` and then `/threads/{thread_id}`. No message-ID decoding, free-text link extraction, native inbox or new discovery endpoint is required. Inboxes remain native-only. The read is bounded by existing event cursor/high-water rules.

New summaries are fixed templates (`Workspace configuration installed.`, `Workspace profile updated.`, `User preferences updated.`), never profile text, changed preference values, subjects, hashes or secrets. Changed layer and resulting version are conveyed by the typed resource/version fields; original correlation is request_id. Operator install events use `actor:{kind:'system',principal_id:<verified operator identity>,agent_id:null}` and an internal immutable install receipt ID; deployment startup cannot invent an operator identity from request JSON. Fixtures in `examples/http/r1-events.json` cover every variant, nullability, unauthorized owner filtering and authorized thread navigation. Task 1 updates their fixture-map entries before implementation.

### Amendment E — R1-owned operator recovery and probe contract

Add `spec/recovery-manifest.schema.json`, `spec/recovery-command.schema.json`, `examples/recovery/r1-manifest.json` and `docs/runbooks/r1-recovery.md`. This is a finite operator protocol on a **separate** operator Worker, never a route on the public product Worker. `POST /operator/recovery` accepts closed discriminated requests for `install`, `capture`, `read-chunk`, `restore`, `write-chunk`, `verify`, `probe`, `resolve-delivery`, `retire`, `resume`, and `status`; it accepts no SQL, arbitrary object names or destinations. The CLI obtains the exact operator HTTPS origin and workspace/environment allowlist from a protected operator config. The operator Worker validates a Cloudflare Access service assertion's signature, configured issuer/audience, `type='app'`, time claims and signed `common_name` (Access service-token client ID) against the explicit operation/target allowlist. Service-token `sub` is empty: do not require a human subject or accept ordinary human JWTs in this operator lane; caller headers alone are not authority. The Access application uses Service Auth policy. CLI sends `CF-Access-Client-Id` and `CF-Access-Client-Secret` from a protected file/FD on every request, never relies on a `CF_Authorization` cookie, and refuses redirects. Bootstrap installation uses the same authenticated operator attribution. The Worker invokes only binding-only WorkspaceDO recovery methods; product credentials/sessions cannot invoke them. Missing Access/provider/operator authority blocks operation. This gateway is separately deployed without a public product binding back to its credential material.

The JSON request is `{operation,workspace_id,capture_id,expected_authority_epoch,operation_id,reason,payload}`, all required and closed; `capture_id` is null only for install/probe. `operation_id` is an operator-generated stable idempotency identity: identical replay returns the same receipt, changed payload conflicts. Payloads are exact: install `{config,verification_bundle}`; capture `{budget}`; restore `{manifest,ledger}`; read-chunk `{index}`; verify `{manifest}`; probe `{}`; resolve-delivery `{delivery_id,disposition:'confirmed_delivered'|'failed_without_redrive',evidence_sha256}`; retire `{}`; resume `{receipt_id,ledger,source_retirement_receipt,cutover_record}` (last two nullable only when resuming the original unchanged capture source); status `{job_id}`. Control payload plus envelope must fit 65,536 bytes; write-chunk is the finite binary exception defined in Task 11. `resolve-delivery` records an operator-attested receiver receipt or explicit permanent failure in an immutable private receipt, never generates ACK or a new attempt, and requires a retained external evidence digest; scope it separately from read/status. Task 4 owns install through this exact route: compare-and-swap requires `expected_authority_epoch` to equal the currently installed epoch (0 for an empty authority), and the reviewed new `config_epoch` must be strictly greater than that installed epoch; skipped epochs are permitted. An identical authenticated `operation_id`/payload replay may return its original receipt before the stale-CAS check only after rechecking current operator authorization for the operation and target; a reused operation ID with changed payload conflicts. Config target must match authenticated gateway environment/workspace. All other operations check the installed epoch before work and before async completion.
