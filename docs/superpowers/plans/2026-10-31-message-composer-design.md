## Browser artifact lane
Add one closed HubClient cookie-only artifact method for stageArtifact/uploadArtifactContent/commitArtifact, using existing generated request/response validators and HttpTransport. Writes require current CSRF. Root-relative same-origin fetch; reject caller origins/auth/runtime headers. Content uses a Blob with declared size <=10 MiB; do not set forbidden Content-Length, do not base64 JSON. Server still independently counts/hash-checks. No automatic retry.

Ephemeral attachment owner stores File/Blob, immutable size/SHA256 metadata, stage and upload idempotency keys, committed metadata and frozen commit key/version only in memory. Reserve count and aggregate bytes before hashing; at most five distinct attached artifacts and 26,214,400 bytes; every file <=10,485,760. Dispose memory/abort local fetch on scope/logout/navigation invalidation; late callbacks fenced by captured generation, scope and item identity. Abort does not claim server rollback.

State machine: selected -> hashing -> staging -> uploading -> committing -> committed; errors distinguish definite rejection from uncertain stage/upload/commit. Only committed IDs enter draft. Text remains independent. Stage loss is held unavailable: no stage retry because historical outcome GC can permit a new allocation even with the same key. Explicit Abandon removes only local state and warns that the server artifact may still exist; selecting a new file/upload is a new deliberate operation, not recovery. Upload loss with known ID offers read-only Check status. Exact current metadata (same ID/workspace/hash/size/owner) uploaded/committed is positive; staged remains unavailable; explicit retry FIRST reads current exact metadata and reuses the frozen upload key, same ID and bytes, never stages a second artifact. Commit loss offers read-only metadata check; only exact committed metadata attaches, uploaded permits deliberate commit with frozen commit key/version (if already dispatched); a newer or mismatched version remains unavailable. Retry always reads exact metadata first. Missing/unreadable/expired metadata remains unavailable; never infer noncommit. Reload drops ephemeral files/keys; only committed artifact IDs survive. UI explains orphan uploads may remain under existing server lifecycle, no new delete/cleanup claims.

## Message references and reply
Payload expands existing refs/artifact_ids/thread_id fields. Current task/artifact references checked with getTask/getArtifact; artifact must be committed and exact workspace. Message reference picker comes from explicitly authorized getThread observations, not guessed IDs or unauthenticated history. Restored message-reference IDs without a currently observed containing thread require deliberate re-selection/revalidation (keep text/reference visibly pending), not invented getMessage endpoint. Every referenced distinct artifact, whether refs or attachment IDs, counts toward count/aggregate limits; metadata reads supply exact byte_size.

Reply action originates from authorized rendered thread message. Fetch thread again before fresh admission, selecting only observed senders/recipients proven in that thread; label this as an observed subset, not a complete participant roster. No new participants may be selected in reply mode. Backend remains authoritative on actual current membership and all participant visibility. A deliberate Start new thread preserves text but clears thread binding and requests explicit recipient choice; never silently converts a denied reply. Prior history isn't copied into draft.

Fresh admission revalidation: capture binding/generation; read current recipients/resources/artifacts/thread with fences after each await; then fresh verifyAuthority LAST so optional 403 clearing the shared HubClient CSRF cannot strand preparation. Server preparation/dispatch repeats actual authorization. Historical reconciliation checks current authority only and leaves historical/resource visibility to the native reconciliation endpoint; archived admission preconditions cannot suppress exact historical evidence. Minimal admission receipt is not current Message DTO: unknown new-thread ID never fabricated; reply known thread can be re-read under current authorization before link. Admission/delivery/ACK/completion remain separate.
