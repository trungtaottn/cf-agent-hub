# R4 — Teams and Extension Contracts Implementation Plan

Status: Implementation plan reviewed · Implementation pending.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development for task-by-task implementation with independent review through the authorized execution environment. Keep shared-checkout mutations sequential and follow the orchestration execution ledger. Steps use checkbox (`- [ ]`) syntax for tracking. Implementation requires an available authorized workspace.

**Goal:** Deliver reviewed team membership, remote MCP, a bounded A2A adapter, one real selected connector, and recoverable retention/quotas/operations, covering F36–F39 and F42.

**Architecture:** Existing operator-provisioned workspaces remain the authority boundary; teams add human memberships inside those workspaces. Protocol adapters and the selected connector reuse native domain commands and durable correlation/outbox records. Retention coordinates SQL metadata with R2 tombstones and recovery manifests; quota reservations serialize with workspace mutations.

**Tech Stack:** Existing locked TypeScript/Cloudflare Worker, Durable Objects/SQLite, R2, Vitest/Workers, UI runner and Wrangler. Remote MCP targets `2025-11-25`; A2A target is specification `v1.0.1` with wire protocol `1.0` and the proposed JSON-RPC subset. Verify upstream schemas and compatible dependencies during implementation; pins are not broad conformance claims.

## Global Constraints

- These are planned capabilities, not implemented endpoints. Baseline OpenAPI has no team administration, remote MCP authorization, A2A endpoint or connector management contract. Task 1 creates reviewed, testable contract amendments before dependent code.
- R1–R3 evidence is prerequisite. Keep one Durable Object/SQLite authority per workspace and private artifact bytes in R2; no network/R2 calls inside SQL transactions.
- Preserve neutral CF Agent Hub and MIT `Copyright (c) 2026 trungtaottn`. No personal branding, credentials or fabricated connector activity.
- No automatic tenant creation, billing, global organization directory, arbitrary runtime hosting, bidirectional sync or Google Drive sync support claim.
- Humans bind to verified issuer and subject. Display/email/work-role labels cannot grant administration or merge identities. Each command rechecks current workspace membership/grant before replay.
- Retain current task states, runtime proof, lease/fence, uncertainty/exhaustion holds and independent acceptance. Remote message text/roles cannot approve or self-accept.
- JSON envelope ceiling 65,536 UTF-8 bytes; attachment ceiling 10,485,760 bytes; message/result association at most 5 and 26,214,400 total bytes. Task/event default page 50, ceiling 200. All new list limits require explicit reviewed finite bounds.
- Completed command outcome retention is at least 24 hours. Existing notification budget remains six total attempts with delays 5, 30, 120, 600, 3,600 seconds, persisted downward jitter in [0.8, 1.0]. Provider import retries require their own reviewed bounded budget; they are not implicitly notification retries.
- Invitation validity, retention, quotas, egress allowlists and operational thresholds have no universal defaults. Explicit validated release policy is required; missing configuration disables affected writes/maintenance rather than making it unlimited.
- Each extension has its own acceptance record. A disabled extension can be accurately deferred but cannot count as a complete R4 release. Logos, routes and mocked provider responses prove no live integration or standards conformance.

## Review Focus

1. Two administrators concurrently remove/demote each other: preserve the reviewed recoverable administrative path — Task 2, `membership.test.ts`.
2. Invitation accepted by the wrong verified principal, or grants shrink during acceptance: consume nothing and grant nothing — Task 3, `invitations.test.ts`.
3. Remote token has a valid signature but wrong resource audience, or MCP session persists after revocation: reject every later operation — Task 4, `remote-auth.test.ts`.
4. Provider pagination fails halfway and omits existing objects: preserve records and show incomplete/stale source; never infer deletion — Task 6, `provider-reconciliation.test.ts`.
5. Cleaner crashes between SQL tombstone and R2 deletion while an approved input or restore reference exists: retain required bytes and resume safely — Task 7, `retention-races.test.ts`.
