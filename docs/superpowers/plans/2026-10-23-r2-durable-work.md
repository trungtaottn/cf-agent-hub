# R2 Durable Multi-Agent Work Implementation Plan

Status: Implementation plan reviewed · Implementation pending.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development for task-by-task implementation with independent review through the authorized execution environment. Keep shared-checkout mutations sequential and follow the orchestration execution ledger. Steps use checkbox (`- [ ]`) syntax for tracking. Implementation requires an available authorized workspace.

**Goal:** Deliver F11–F26, F29, F34 and F40 as durable, authorized multi-agent work with independent acceptance, native clients, an accessible board, and a rehearsed complete recovery set.

**Architecture:** The Worker authenticates and routes each request to the workspace's Durable Object; one synchronous SQLite transaction owns each domain change, event, outbox insertion and sanitized replay outcome. R2 stores immutable bytes behind committed artifact metadata and uses runtime proofs, leases and fences to separate durable agent identity from one execution attempt. HTTP, CLI and UI call the same commands; external effects and object-store operations never run inside SQL transactions.

**Tech Stack:** TypeScript, Cloudflare Workers, SQLite-backed Durable Objects, private R2, the verified and locked R1 toolchain, Vitest with the selected Workers runtime integration, Wrangler, and the R1 UI/accessibility runner. Verify compatibility against the lockfile rather than upgrading to a presumed latest version.

## Global Constraints

- R1 must have reproducible acceptance evidence. Import its final `ActorContext` and `CommandContext` from `src/workspace/context.ts`, including trusted `sessionId:string|null`, and its synchronous `WorkspaceTransaction` from `src/storage/transaction.ts`. Do not redeclare an older context. Every human mutation/replay rechecks the server session handle, expiry, workspace/principal binding and revocation inside the actual transaction, including after awaits. Treat all file paths below as planned paths, not evidence of existing implementations.
- All external JSON fields use the exact snake_case OpenAPI DTOs. IDs are validated opaque strings. Do not rename states: task states are `backlog`, `ready`, `doing`, `waiting`, `review`, `done`, `cancelled`; run statuses are `active`, `paused`, `submitted`, `failed`, `expired`, `cancelled`. Every ended run has `ended_at`; a paused run never resumes.
- One active run per task; `active_run_id` is non-null only for Doing. Every new claim creates a new run and greater task-local fence. Valid renewal changes only run version/lease, not task/proposal versions. Server time and trusted entropy determine authority; tests inject deterministic equivalents. Resolve `CommandContext.nowMs` from the workspace trusted clock at the actual mutation transaction boundary, never from a client or stale Worker enqueue timestamp; repeat time checks after asynchronous byte verification and before committing.
- Execution lease: 60 seconds. Recommended run heartbeat interval: 20 seconds. Runtime presence expiry: 90 seconds. Completed idempotency outcomes retained for at least 24 hours. Expiry applies at the boundary (`now >= deadline`) even without a cleanup alarm.
- JSON request envelope: 65,536 UTF-8 bytes. Structured references: 8,192 serialized UTF-8 bytes. Artifact: 10,485,760 bytes. At most five attachments and 26,214,400 aggregate bytes per message/result. Task/event pages: default 50, ceiling 200. Preserve other OpenAPI list bounds and R1 inbox/thread limits.
- Workspace WIP, retry limit, upload expiry and eligibility must be explicitly configured before enabling the affected operation. Task 1 supplies a closed policy amendment; its fixture numbers are test/deployment choices, never universal capacity promises. No missing policy means unlimited execution.
- Current authorization is rechecked before successful replay, on every cursor page, and at every external dispatch. A credential's `project_ids:null` and `project_ids:[]` remain distinct. Profile labels, work roles, model names and imported text cannot grant permissions.
- Human-only agent/credential management rejects native callers even with forged scope claims. Native claim, execution, presence heartbeat and artifact writes require the issuing active credential AND its exact runtime proof. Never persist raw native/runtime tokens in logs, audit, replay outcomes, browser storage or backup exports.
- Preserve canonical approval schemas, versions, checkpoints, exact immutable `application/json` input binding `{artifact_id,sha256}`, and approved-intent PATCH restrictions. R2 must not expose request-decision, approval mutation/read UI or adapter approval tools as working features. R3 owns their activation; its disabled routes fail through the existing unavailable-feature contract and never fabricate Waiting or approval records.
- ACK and successful delivery never change task state. Submit enters Review; independent acceptance alone enters Done. Exclude both submitting principal and submitting agent, including alternate credentials and runtimes.
- `outcome_unknown` and `retry_exhausted` block Ready, Requeue and Claim. No hold-clear or retry-budget reset endpoint. Reconciled replacement work preserves provenance. Fencing protects hub state; it cannot guarantee exactly-once external actions.
- Keep neutral CF Agent Hub product copy and MIT `Copyright (c) 2026 trungtaottn`. Do not add personal identities, private provenance, production credentials, arbitrary code hosting or simulated connectors.

## Review Focus

1. A static R1 identity adopted into the R2 registry must not regain revoked access or broaden project grants: Task 2, `static_adoption_preserves_identity_revocations_and_ceiling`.
2. Lease expiration and proof revocation during a run must win without waiting for an alarm: Tasks 4–5, `expiry_at_deadline_denies_before_alarm` and `revocation_blocks_replay_and_active_owner`.
3. Cleanup racing a late upload/commit must never delete newly committed bytes or revive an expired intent: Task 6, `cleanup_tombstone_wins_late_upload` and `commit_wins_cleanup_without_byte_loss`.
4. A stale import preview or catalog remap must not mutate live approved intent or overwrite local edits: Tasks 3 and 9, `remap_rejects_approved_intent_and_live_work` and `changed_external_row_never_overwrites_local_task`.
5. Recovery from an older database must not revive post-checkpoint credentials, runtime proofs, leases or duplicate external delivery: Task 12, `restore_epoch_and_current_revocations_block_old_authority` and `outbox_without_receipt_remains_uncertain`.
