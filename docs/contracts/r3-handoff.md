## Narrow bridge surface

`packages/client/src/native-types.ts` aliases seven canonical schemas: Task, Run, Proposal, Approval, TaskRequestDecisionRequest, ApprovalDecisionRequest and TaskCommandResult. The last two request roots are added to the existing generator, not hand-written or activated as operations. `NativeInvoker.invoke` preserves `NativeClient.call`'s generic request/output relationship. `createNativeInvoker` delegates to an already constructed trusted native client without retry, reshaping, new fetch, credentials or domain logic.

`ResponseFor` is the existing complete parsed client result, not only its data and not a fabricated raw HTTP envelope. Preserve success/error/status/request correlation, optional page and the artifact binary result with null requestId. Explicit runtime proof/provider configuration remains trusted host plumbing, never tool fields. Type aliases do not sanitize runtime JSON or authenticate an actor.

The operation inventory still excludes requestTaskDecision, listApprovals, getApproval, approveApproval and rejectApproval. Human approve/reject remain HUMAN-only. Schema availability does not enable a route, action, permission or operation. Unknown authority-bearing body fields remain rejected by the actual native client before provider acquisition.

## Test ownership and evidence

`test/helpers/runtime-suites.ts` explicitly selects `test/approvals/native-bridge.test.ts` for Node. It reserves the future Node contract test and future Workers approval glob, excluding both Node files from Workers. Reserved absent files are not executed evidence. Root TypeScript already includes these test and client paths.

The bridge tests exercise the actual client with synthetic transport fixtures: generated closed schemas, all three decision versions, exact input digest shape, unknown identity fields, native result/correlation/key preservation and unavailable-operation zero-dispatch. Compile fixtures require all seven aliases to equal their generated types and reject missing versions/camelCase/identity fields. They are not live native or browser authentication evidence.

Local test details and exact final CI belong in the issue/PR checkpoint; focused checks do not imply full source or acceptance success. Existing native-conformance/provenance/currentness/deadline tests remain applicable. The design reuses TypeScript [indexed access types](https://www.typescriptlang.org/docs/handbook/2/indexed-access-types.html) and the project's existing generic call signature rather than adding a new transport framework.
